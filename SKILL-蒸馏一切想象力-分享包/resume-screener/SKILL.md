# SKILL.md — resume-screener（简历批量筛选）

## 一、技能简介

本技能用于招聘场景下的简历批量筛选：从一个本地文件夹读取多份 PDF 格式求职简历，依据公司既定的招聘标准（销售人员招聘标准、开发人员招聘标准）对每位候选人逐项评估打分，再参照本地报告模板生成一份中文筛选报告。报告默认只落盘保存；**仅当用户明确要求发送时**，才通过 SMTP 邮件把报告发出去。

设计原则：把「确定性的机械操作」（发现文件、提取文本、渲染报告、发邮件）交给脚本，把「需要判断的分析工作」（理解简历内容、对照招聘标准打分、撰写评语）交给模型本身。这样既稳定又灵活。

## 二、何时触发

当用户的请求包含以下意图时触发本技能：

- 筛选 / 批量看一批求职简历
- 按公司招聘标准对候选人打分、排名
- 评估销售岗位或开发岗位的求职者
- 生成简历筛选 / 招聘评估报告
- 用户提到「筛选简历」「简历分析」「评估候选人」「sales 简历」「开发简历筛选」等关键词

触发关键词：

```
筛选简历, 简历筛选, 招聘筛选, 简历分析, 批量看简历, 评估候选人,
sales 简历, 开发简历筛选, 简历打分, 候选人排名, resume screening
```

## 三、使用流程

### 步骤 0：与用户确认必要输入

在动手前，向用户确认以下信息（未提供时主动询问，不要默认猜测）：

| 输入项 | 说明 | 默认值 |
|--------|------|--------|
| 简历文件夹路径 | 存放 PDF 简历的本地目录 | 无，必填 |
| 招聘标准文件 | 销售 / 开发岗位的招聘标准 Markdown | 本技能内置占位文件 `references/sales_hiring_criteria.md`、`references/dev_hiring_criteria.md` |
| 报告模板 | 报告骨架 Markdown | 本技能内置 `assets/report_template.md` |
| 是否发送邮件 | 是否需要把报告通过邮件发出 | **默认不发送**；仅当用户明确要求时才发送 |
| 收件人邮箱 | 发送邮件时的收件地址 | 仅在用户要求发送时必填 |

> 关于「是否发送邮件」：这是一个需要用户明确授权的动作。**默认一律不发送**。只有当用户说出类似「把报告发给我」「发送到 xxx@xxx.com」「邮件发一下」时，才进入步骤 5 的发送环节。不确定时，先问一句再发。

### 步骤 1：提取简历文本

运行本技能自带的提取脚本，把文件夹里的 PDF 批量转成文本：

```bash
python scripts/extract_pdfs.py "<简历文件夹路径>" --output <工作目录>/resumes.json
```

脚本会：

1. 递归扫描目录下所有 `.pdf` 文件；
2. 优先用 `pdfplumber` 提取文本，失败时回退到 `PyPDF2`，再失败则标记为 `needs_manual_read: true`；
3. 把每份简历的文件名、路径、提取到的文本、提取方式写入 `resumes.json`。

**回退机制**：如果环境中没有安装任何 PDF 解析库，或者某份简历被标记为 `needs_manual_read: true`（常见于扫描件、图片型 PDF），请改用 Read 工具逐份直接读取这些 PDF —— Read 工具能直接读取 PDF 内容（含 OCR）。把补充读到的文本合并进评估上下文即可。

依赖安装（首次使用时按需）：

```bash
pip install -r requirements.txt
```

### 步骤 2：加载招聘标准并逐份评估

读取 `resumes.json`，对每份简历执行评估：

1. 先判断该候选人应聘的岗位类别（销售 / 开发 / 其他）。如果简历中未明确，可结合投递岗位说明或询问用户；无法判断时按「其他」处理并在报告中标注。
2. 读取对应的招聘标准文件（销售读 `references/sales_hiring_criteria.md`，开发读 `references/dev_hiring_criteria.md`）。
3. 把招聘标准里的每一条要求作为评分项，逐条对照简历内容打分并给出依据。打分采用招聘标准文件中定义的分制（默认每项 0–5 分）。
4. 汇总每位候选人的总分、岗位类别、各评分项明细、亮点、风险点、结论（推荐进入面试 / 备选 / 不推荐）。

把评估结果整理成结构化 JSON，保存为 `<工作目录>/evaluations.json`，单条结构如下：

```json
{
  "filename": "张三-销售.pdf",
  "candidate_name": "张三",
  "position_type": "销售",
  "items": [
    {"criterion": "沟通表达能力", "score": 4, "max": 5, "evidence": "简历中提到……"},
    {"criterion": "销售业绩", "score": 5, "max": 5, "evidence": "曾达成……"}
  ],
  "total_score": 23,
  "max_score": 30,
  "highlights": ["……"],
  "risks": ["……"],
  "conclusion": "推荐进入面试"
}
```

### 步骤 3：生成筛选报告

用脚本把评估结果按报告模板渲染成最终报告：

```bash
python scripts/generate_report.py \
  --evals <工作目录>/evaluations.json \
  --template assets/report_template.md \
  --output <工作目录>/简历筛选报告.md
```

脚本会读取模板、填入统计概览与每位候选人的评分明细，输出一份完整的 Markdown 报告。

> 也可以由你（模型）直接参照 `assets/report_template.md` 的结构手写报告，脚本只是把机械的填充工作自动化。两种方式择一即可，结果都应与模板结构一致。

### 步骤 4：把报告交付给用户

报告生成后，把文件路径告诉用户，并简要汇报：

- 共筛选多少份简历（销售 X 份、开发 Y 份、其他 Z 份）；
- 推荐进入面试 / 备选 / 不推荐各几人；
- 报告文件的绝对路径。

到这一步，**默认就结束了**——报告已落盘，不发邮件。

### 步骤 5：（仅当用户明确要求）发送邮件

只有当用户明确要求发送时，才执行这一步。先确认收件人邮箱与 SMTP 配置就绪，再运行：

```bash
python scripts/send_report.py \
  --report "<报告路径>" \
  --to "<收件人邮箱>" \
  [--cc "<抄送邮箱>"] \
  [--subject "简历筛选报告"] \
  --config <smtp 配置文件>
```

SMTP 配置通过配置文件或环境变量提供，**绝不硬编码在脚本里**（详见 `scripts/send_report.py` 顶部说明）。配置未就绪时，提示用户补充，不要擅自用一个假配置发送。

## 四、输入规范

- 简历：PDF 格式，放在同一个文件夹内（支持递归子目录）。
- 招聘标准：Markdown 文件，每条要求用列表项给出，可附权重 / 分制说明（参见 `references/` 下占位文件）。
- 报告模板：Markdown 文件，含 `{{summary}}`、`{{candidate_table}}`、`{{details}}` 等占位标记（参见 `assets/report_template.md`）。

## 五、输出规范

最终交付物为一份中文 Markdown 报告，结构遵循 `assets/report_template.md`：

1. 报告概览（总数、岗位分布、各结论人数）
2. 候选人排名总表（姓名 / 岗位 / 总分 / 结论）
3. 每位候选人的评分明细（逐项得分 + 依据 + 亮点 + 风险 + 结论）

## 六、注意事项

1. **默认不发邮件**：发送是需用户明确授权的外部动作，未授权时只落盘报告。
2. **招聘标准可替换**：内置的销售 / 开发招聘标准为占位文件，请替换为真实公司文档后再正式使用。
3. **评分客观有据**：每一项打分都要在 `evidence` 中写明来自简历的依据，避免无来源的主观臆断。
4. **隐私合规**：简历含个人信息，处理时注意保密；报告与中间文件建议存放在受限目录，用完可清理。
5. **PDF 提取兜底**：扫描件 / 图片型 PDF 可能提取不到文本，务必走 Read 工具回退，不要直接判 0 分。
6. **报告语言**：默认输出简体中文报告。
